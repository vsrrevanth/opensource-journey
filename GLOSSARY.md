# 📖 Open Source & Git Glossary (plain English)

- **Repository ("repo")** — A project's codebase + history + issues + PRs, hosted publicly (e.g. on GitHub).
- **License** — Legal rules for using/contributing (e.g. Apache-2.0). Contributions fall under it.
- **Maintainer** — Person with rights to review/merge changes. Usually volunteers. Respect their time.
- **Contributor** — Anyone whose contribution (code, docs, etc.) was accepted. That's you after PR #1.
- **Issue** — A ticket for a bug, feature request, or task. Discussion happens here *before* code.
- **Pull Request (PR)** — Your proposed change; you ask maintainers to "pull" your commits in.
- **Fork** — Your personal copy of the repo under your account. You push here, not to the original.
- **Branch** — A named line of work. Never work on `main`/`master`; make a branch like `fix-typo`.
- **Commit** — A saved snapshot of changes with a message.
- **origin vs upstream** — `origin` = your fork; `upstream` = the real project repo.
- **good first issue / help wanted** — Labels marking beginner-friendly issues.
- **CI (Continuous Integration)** — Automated checks (build/test/lint) that run on your PR. Green = good.
- **Code review** — Maintainers comment asking for changes. Normal and helpful, not criticism of you.
- **Squash / merge** — How an approved PR is combined into the main history.
- **CLA** — Contributor License Agreement; some projects require signing one. (stern does not.)
- **DCO / sign-off** — A `Signed-off-by` line certifying you wrote the code. Added with `git commit -s`.
- **gopls / Go extension** — VS Code tooling for Go: autocomplete, jump-to-definition, inline errors.
